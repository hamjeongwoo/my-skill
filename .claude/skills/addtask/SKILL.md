# /addtask — 할 일 관리

사용자는 작업 지시를 많이 한다. 이 커맨드는 그 지시를 일감으로
남기고, 진행 사항과 연결된 문서(설계·계획·커밋·메모리)를 한 곳에서 보게 한다.

모든 출력은 한국어로 쓴다. 사용자에게 묻는 것은 `AskUserQuestion` 팝업으로 한다.

## 문서는 둘이다: 메인 체크아웃의 `docs/TODO.md` 와 `docs/DONE.md`

| 문서 | 담는 것 |
|---|---|
| `docs/TODO.md` (할 일) | **진행 중 · 대기 · 보류** 일감만. 완료 절이 없다 |
| `docs/DONE.md` (완료) | **완료** 일감만. 최근 것이 위 |

- **완료된 일감을 `TODO.md` 에 남기지 않는다(강제).** 일감이 완료되면 그 항목 전체를
  `TODO.md` 에서 **잘라내** `DONE.md` 맨 위(머리말 바로 아래)에 붙인다. 같은 커밋에서
  두 파일을 함께 고친다 — 한쪽만 고친 상태로 커밋하지 않는다(일감이 사라지거나 두 번 생긴다).
- 완료 뒤에 생긴 일(후속 확인 등)은 `DONE.md` 의 그 항목에 적는다. 다시 일이 되면 새 일감을
  만들거나 `진행 T-번호` 로 `TODO.md` 에 되돌린다.
- **항상 메인 체크아웃(master 가 체크아웃된 저장소 루트)의 이 두 파일만 고친다.**
  worktree 안의 사본을 고치면 브랜치마다 문서가 갈라져 병합 때 충돌한다.
- 메인 체크아웃 경로 찾기: `git rev-parse --git-common-dir` 의 부모 디렉터리.
  (이 저장소는 `C:\Users\hjw\claudeProject\auto-stock-investment`)
- 고친 뒤 **그 두 파일만** 커밋한다: `git -C <메인> add docs/TODO.md docs/DONE.md` →
  `git -C <메인> commit -m "docs(todo): <무엇을 했는지>"` (끝에 빈 줄과
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`). 메인 체크아웃에 다른
  변경이 있어도 건드리지 않는다. **push 하지 않는다**(로컬 전용 저장소).
- 두 파일은 CRLF 다 — 고칠 때 줄바꿈을 유지한다.
- 날짜는 KST `YYYY-MM-DD`.

## 인자에 따른 동작

`$ARGUMENTS` 를 보고 첫 단어로 갈라진다.

| 인자 | 동작 |
|---|---|
| (없음) 또는 `목록` | `TODO.md` 의 진행 중·대기·보류 일감을 표(번호·제목·상태·갱신일·다음 할 일)로 보여준다. 문서는 고치지 않는다 |
| `완료 T-번호` | 상태를 `완료` 로, 진행 기록에 `- 날짜 상태 → 완료` 한 줄, 갱신일 고침 → 항목 전체를 `TODO.md` 에서 잘라 `DONE.md` 맨 위로 옮긴다 |
| `진행 T-번호` / `보류 T-번호` / `대기 T-번호` | 그 일감의 상태를 바꾸고 `TODO.md` 의 해당 절로 옮긴다. 진행 기록에 `- 날짜 상태 → <새 상태>` 한 줄, 갱신일 고침. 일감이 `DONE.md` 에 있으면 거기서 잘라 `TODO.md` 로 되돌린다 |
| `메모 T-번호 <내용>` | 진행 기록에 `- 날짜 <내용>` 한 줄(그 일감이 있는 문서에서) |
| `연결 T-번호 <경로 또는 커밋>` | 연결 목록에 한 줄. 파일이면 저장소 기준 상대 경로 링크로 |
| 그 밖의 모든 것 | **새 일감 추가**(아래) |

번호가 없거나 모르는 번호면(두 문서 어디에도 없으면) 문서를 고치지 않고 팝업으로 어느 일감인지 묻는다
(비슷한 제목 후보를 선택지로).

## 새 일감 추가

1. **두 문서를 합쳐** 가장 큰 번호 + 1 로 번호를 정한다(`T-001` 형식, 번호는 절대
   재사용하지 않는다 — 완료로 옮긴 번호도 쓰인 번호다).
2. 제목은 요청을 20자 안팎으로 줄인 것. 요청 요지는 사용자의 말을 바꾸지 않고
   한두 문장으로 적는다.
3. 이미 같은 일감이 있으면(`DONE.md` 포함) 새로 만들지 않고 팝업으로 묻는다
   ("T-00x 에 메모로 붙일까요 / 새 일감으로 만들까요").
4. 상태는 `대기`, `TODO.md` 의 대기 절에 넣는다. 연결 문서가 이미 있으면(대화에서 언급된 설계·계획·메모리) 연결에 넣는다.
5. 커밋한 뒤, 추가한 항목을 보여주고 **다음 단계를 팝업으로 묻는다**:
   지금 시작(설계가 필요한 작업이면 brainstorming 부터) / 대기로 둠 / 다른 일감보다 먼저.

## 일감 형식 (두 문서 같음)

```markdown
### T-012 제목
- 상태: 대기 · 요청 2026-09-30 · 갱신 2026-09-30
- 요청: 사용자 요청의 요지
- 연결: [설계](docs/superpowers/specs/....md) · [계획](docs/superpowers/plans/....md) · 커밋 `abc1234` · 메모리 `name`
- 다음: 다음에 할 한 가지(없으면 생략)
- 진행:
  - 2026-09-30 일감 추가
```

`TODO.md` 절 순서: `## 진행 중` → `## 대기` → `## 보류`. **`## 완료` 절을 만들지 않는다.**
`DONE.md` 는 절 없이 항목만, 최근 완료가 위.
상태 단어는 넷뿐이다: 진행 중 / 대기 / 보류 / 완료.

## 자동 갱신 (커맨드 없이도)

전역 지침(`~/.claude/CLAUDE.md` "할 일 문서 갱신")에 따라, 일감과 관련된 다음 일이
생기면 Claude 가 스스로 그 항목을 고친다 — 설계 승인, 계획 커밋, 구현 커밋, master
병합, 서버 배포, 검증, 완료. 진행 기록 한 줄 + 연결 추가 + 상태·다음·갱신일.
**완료가 되면 커맨드 없이도 위 `완료 T-번호` 와 똑같이 `DONE.md` 로 옮긴다.**
새 일감은 `/addtask` 로만 추가한다.
